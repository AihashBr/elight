# 0013: File IDs and `files.json`

- Status: accepted
- Date: 2026-10-24

## Decision

Every file the engine refers to has a fixed ID. A `files.json` at the project root, created with the project, maps each ID to the file's current path. Inside the engine, files are referred to by ID, not by path. Renaming or moving a file only changes its entry in `files.json`.

```json
{
  "version": 1,
  "files": {
    "f3k9x2": "objects/primitives/meshes/cube.js",
    "a7m1q8": "attributes/movement.js",
    "s0p4z6": "scenes/main.json",
    "t5r2w9": "assets/textures/wood.png"
  }
}
```

## Which files

- With an ID: everything the engine refers to: `objects/`, `attributes/`, `scenes/` and `assets/`.
- Without an ID (fixed paths): `index.html`, `game.json`, `files.json` and `libs/`.

## Where IDs are used

| Place | Before | Now |
|---|---|---|
| Object `type` in a scene (decision 0007) | `"primitives/meshes/cube"` | `"f3k9x2"` |
| Attribute `type` in a scene (decision 0011) | `"movement"` | `"a7m1q8"` |
| `startScene` in `game.json` (decision 0009) | `"scenes/main.json"` | `"s0p4z6"` |
| `asset` property values (decision 0006) | `"textures/wood.png"` | `"t5r2w9"` |

## Paths for people and the AI

IDs are not readable, so people and the AI keep using paths, and the engine converts:

- Terminal and AI commands take paths (`world add primitives/meshes/cube`).
- Code in classes uses paths (`this.owner.getAttribute('movement')`).
- The properties panel, the world items menu and the logs show paths.

## Keeping it in sync

- Every create, move, rename and delete (editor, AI or terminal) goes through the projects service, which updates `files.json` in the same step.
- When a project is opened, the editor checks the folders against `files.json`: a file with no ID gets one; an ID whose file is gone is reported in the logs.
- Deleting a file removes its entry. Anything that used that ID is handled as a missing class or asset (decision 0006).
- IDs are short random strings, generated by a helper (decision 0005), and never reused.

## `index.html`

The game reads `files.json` right after `game.json`, to turn IDs into paths before it loads scenes, classes and assets.

## Why

- Renaming or moving a file never breaks scenes: one entry changes, nothing else.
- The same approach as Unity and Godot, which also give files stable IDs.
